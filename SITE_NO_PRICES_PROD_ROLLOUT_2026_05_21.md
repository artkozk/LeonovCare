# Site Release: Production Without Public Prices (2026-05-21)

## Цель релиза

Сделать публичную версию сайта без отображения цен и без ценовой риторики в интерфейсе, чтобы страницы выглядели как продукт, где ценники не были частью пользовательского сценария.

## Почему это сделано именно так

1. Запрос продукта: не просто скрыть суммы, а убрать ощущение «раньше здесь были цены».
2. Риск частичного скрытия: если оставить ценовые заголовки/лейблы (например, «Тариф», «Стоимость», «Цена по запросу»), пользователь все равно видит следы прежней логики.
3. Для чистого UX убраны:
   - numeric price values;
   - ценовые формулировки в ключевых CTA и FAQ;
   - price-блоки в карточках, где это критично для визуального паттерна.
4. Сохранена структура сценария (форматы, этапы, roadmap, запуск через Telegram), чтобы не ломать продуктовый поток без ценников.

## Что изменено (файлы)

1. `script.js`
   - Добавлен флаг `hidePricesCompletely` из `config.js`.
   - Добавлен слой нормализации `displayText`/`displayPrice` для удаления price-риторики в рендере.
   - Убран вывод price-блоков в карточках при активном флаге.
   - Очищены ценовые фразы в bot-message маршрутизации (формулировки про «тариф/оплату» заменены на «формат/этапы запуска»).
   - Для autoapply-калькулятора включены нейтральные тексты без валютной экспозиции при активном флаге.

2. `config.js`
   - Включен `hidePricesCompletely: true`.
   - Переписаны верхнеуровневые price-массивы и тексты `servicePillars/serviceTariffs/autoapply` в формат «без ценников».
   - Удалены денежные значения из ценовых полей сервисных карточек (оставлен форматный сценарий).

3. Контентные HTML-страницы (видимая часть UI)
   - `index.html`
   - `directions.html`
   - `autoapply.html`
   - `interview-helper.html`
   - `zero-offer.html`
   - `interview-prep.html`
   - `grade-salary.html`
   
   Во всех перечисленных страницах заменены ценовые формулировки/CTA на нейтральные форматы запуска.

## Что НЕ изменено

1. Функциональность переходов в Telegram и маршрутизация через deep-link.
2. Общая структура сайта и ключевые продуктовые блоки (roadmap, направления, FAQ, CTA-поток).
3. Логика зарплатного графика по рынку направлений (это рыночная аналитика по зарплатам, а не прайс услуг).

## Проверка качества изменений

1. Синтаксис `script.js` проверен командой:
   - `node --check script.js`
2. Поиск по репозиторию на явные ценники в публичных HTML:
   - убраны вхождения `₽` и прямые pricing-формулировки в пользовательских блоках.
3. Проверка того, что price-блоки не рендерятся при `hidePricesCompletely: true`.

## План безопасного деплоя

1. Сделать backup текущих продовых site-файлов в timestamp-папку.
2. Выгрузить только измененные site-файлы (без backend/bot).
3. Проверить сайт после выката по ключевым страницам.

## Быстрый rollback

### Вариант A (рекомендованный, файловый rollback на сервере)

1. Зайти в backup-каталог релиза и вернуть файлы:
   - `cp <backup_dir>/config.js /main/LeonovCare/LeonovCare/config.js`
   - `cp <backup_dir>/script.js /main/LeonovCare/LeonovCare/script.js`
   - аналогично для измененных HTML-файлов.
2. Проверить страницу в браузере.

### Вариант B (git rollback по commit)

1. В целевой ветке сделать revert конкретного релизного commit.
2. Выкатить revert в прод стандартным процессом.

Оба варианта специально оставлены, чтобы откат занимал минимум времени при любом состоянии рабочей копии на сервере.
